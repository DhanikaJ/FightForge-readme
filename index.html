⚡ The pitch

Elite fighters get sensor-packed gyms and a sports-science team. Everyone else gets a notebook and a coach yelling “that was a good one!”

FightForge closes that gap. Prop a phone against a water bottle, hit Start, and it watches the session: counting strikes, spotting takedowns, tracking who is who during sparring, logging how you recover, and handing the numbers to an AI coach that actually knows your session. Everything runs on a mid-range Android phone.

Existing options need $200+ smart gloves (strikes only, no grappling), or they are glorified stopwatches. FightForge covers the full MMA lifecycle in one app: train → track → recover → get coached → run the gym.

🔒 Why the source isn't public: FightForge started as a university module (Handheld Device Programming II) and is intended to grow into a commercial client product. This page is the public technical showcase. Code walkthroughs are available on request.

🧠 The vision pipeline (the part I'm proudest of)

MediaPipe alone can't track two fighters, and a phone in a human hand shakes. So FightForge chains three cheap signals into something more reliable than any one of them:

  1. 1

    GyroStabiliser: “is the camera even steady?”

    Integrates gyroscope angular velocity between frames. If the camera rotated more than 0.15 rad (≈ 8.6°), the frame's motion is vetoed before it can create a phantom punch.

  2. 2

    HSV colour profiling: “who is who?”

    Tap each fighter's torso once. The app builds an HSV profile and matches pose regions against it on a 160×120 bitmap. Hue is far less sensitive to gym lighting than RGB.

  3. 3

    MediaPipe Pose Landmarker (numPoses = 2)

    Two independent 33-point skeletons per frame, with a GPU → CPU → lite-model fallback cascade so it launches on more devices.

  4. 4

    PoseEventDetector: “was that a strike?”

    Wrist velocity, arm-extension direction and opponent-zone validation. Strikes are classified head vs body from the motion centroid.

  5. 5

    SparringStatsTracker: “what does it mean?”

    Thread-safe per-fighter counters with combo-burst detection (3+ strikes in a 2 s window).

Honest limit: in clinches where torsos overlap, identity accuracy drops to ~74%. By design, ambiguous frames are skipped rather than guessed, so the stats stay trustworthy at the cost of slight undercounting.

🛠️ Hard problems, solved

The interesting bugs. Each one reshaped the design.

📷 The camera-shake phantom punches

ProblemHandheld movement changed the whole frame, so frame differencing counted a flood of “strikes” that never happened.
FixGyroscope-based motion veto (GyroStabiliser), with no optical flow needed. False positives dropped an estimated 87% in a deliberate shake test.

🧍🧍 Landmark “hopping” between fighters

ProblemSingle-pose MediaPipe kept jumping between the two bodies, so the opponent's punches were credited to you.
FixnumPoses=2 plus colour-profile torso matching to assign each skeleton to Fighter A or B. Shipped as parallel _v2 classes so the stable v1 pipeline was never put at risk.

📵 Offline-first Firestore, configured twice

ProblemPersistence settings can only be applied once per instance, and two repositories both initialised it, so the second call crashed.
FixGuarded settings call that tolerates the conflict and keeps the first valid configuration, so full offline writes still work.

📝 Notes that outlive the screen

ProblemSession notes are created live, but the session's Firestore ID doesn't exist until the summary screen. Notes in memory would die with the process.
FixDraft pattern: notes stream to sessionNotesDraft/{startMs}/notes, then get copied to the canonical path on save.

🎙️ The half-second voice note crash

ProblemAndroid's MediaRecorder.stop() throws if called within ~500 ms of start, which is easy to trigger with an accidental mic tap.
FixCatch, delete the corrupt file, show a helpful toast. No crash.

📐 Android 15's 16 KB page size

ProblemNative .so libraries from MediaPipe and CameraX crashed on launch on 16 KB-page targets.
FixUncompressed JNI packaging (useLegacyPackaging = false) so the linker aligns pages at install. Verified on 16 KB emulator targets.

🏗️ Architecture

A strict six-layer design (UI → ViewModel → Repository → Foundation → Intelligence → Hardware) so the riskiest subsystem, the AI vision pipeline, could be built and tested in isolation.

🧩 Details recruiters might enjoy

  • Battery-aware: a low-battery broadcast drops frame processing to every third frame.
  • Boot-proof reminders: daily 08:00 training and 21:00 recovery alarms are re-scheduled after reboot or app update.
  • Polish pass: shared skeleton/shimmer loading helper, inline retry error cards, DiffUtil on five adapters, haptic 3-2-1-GO countdown, relative timestamps.
  • Permissions done right: every dangerous permission is requested at runtime with a rationale dialog. Voice notes never leave the device without consent.
  • Notification channels: four separate channels (session, sparring, reminders, coach notices).

🧪 Testing approach

JUnit tests cover colour-zone logic, fighter colour profiles, models, the session manager and analytics view-model states. Espresso instrumented tests cover login, registration and sparring-setup navigation (standard vs dual-AI routing) using TestNavHostController. A custom CountingIdlingResource on the countdown overlay removes flakiness from animated UI, and BoundedMatchers verify the sparring-summary RecyclerView. Known gaps (no DI framework for mocking singletons) are documented openly in the full report.
